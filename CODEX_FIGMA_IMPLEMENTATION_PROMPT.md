# Промпт для Codex: доработка Wandero по макету Figma

Ты работаешь в репозитории проекта Wandero. Нужно довести до согласованного рабочего состояния frontend и backend, сверяясь с актуальным макетом Figma через официальный Figma MCP.

## Макет и контекст продукта

Figma: https://www.figma.com/design/UCuuOmm54OdzY4FdlQjWd7/Chronograph-SPB-%E2%80%94-Walks---Routes?node-id=1-2&p=f&t=YVrqfY6GgjRYJgDI-0

Это приложение для пеших прогулок по Санкт-Петербургу. Пользователь должен находить места, открывать готовые маршруты и собирать собственную прогулку из достопримечательностей и близлежащих интересных мест. Внутри карточек мест нужны исторические описания. События пока не входят в MVP.

Сохранить визуальное направление макета: тёплый бежевый фон, приглушённые зелёные и коричневые акценты, спокойная картографическая подача. Популярность маршрута показывать тематическим счётчиком пройденных прогулок (например, следы и «N прошли»), если эта идея не противоречит актуальному макету. Не добавлять звёздные рейтинги, события или декоративные функции без основания в макете и продуктовой концепции.

## Обязательный порядок работы

1. В начале изучи `AGENTS.md`, README и инструкции проекта, затем выполни `git status --short`. Не сбрасывай изменения, не перезаписывай и не удаляй пользовательскую работу. Перед правками пойми текущую архитектуру и уже существующие изменения.
2. Проверь, доступен ли в этой сессии официальный Figma MCP. Используй его для файла выше: извлеки file key `UCuuOmm54OdzY4FdlQjWd7` и node ID `1:2`. Создай Figma session согласно требованиям MCP. Для чтения дизайна сначала загрузи обязательную инструкцию `figma-design-to-code`, затем изучи контекст указанного узла и структуру страниц; найди соответствующие desktop и Android/mobile экраны, если они есть. Не угадывай ID узлов: получи их из metadata.
3. Сопоставь реальные экраны Figma с текущими desktop и Android реализациями. Зафиксируй короткий перечень расхождений: экраны, состояния, токены, навигация и поведение. Макет — источник визуальных решений; существующую архитектуру и компоненты проекта нужно повторно использовать, где это уместно.
4. Если Figma MCP недоступен, файл не открывается или нет прав, продолжай независимый аудит кода и реализацию по доступной продуктовой концепции. Явно укажи в отчёте, что именно не получилось проверить в Figma; не утверждай, что макет был прочитан или изменён. Не обходи авторизацию браузера и не ищи секреты в окружении.
5. Проследи полный пользовательский сценарий через UI, API, доменную логику и хранилище. Определи фактические пробелы и реализуй необходимые части, не ограничиваясь косметическим рефакторингом.

## Требования к функциональности

- Главный сценарий: поиск места, просмотр мест, просмотр готовых маршрутов и создание своей прогулки.
- Каталог мест: поиск и нужные фильтры, выбор места из списка или карты, карточка с описанием и исторической справкой, ближайшие места.
- Готовые маршруты: маршрут состоит из упорядоченных остановок, показывает описание, список мест, расстояние и длительность, если эти значения достоверно доступны, а также счётчик прошедших маршрут пользователей, если поддерживается продуктовой моделью.
- Своя прогулка: выбрать стартовое место поиском или на карте, добавить близлежащие места, менять порядок и удалять остановки, видеть маршрут на карте, сохранить/открыть прогулку согласно имеющейся модели пользователя и авторизации.
- Состояния интерфейса: загрузка, пустой результат, ошибка API, отсутствие геометрии/данных, успешное сохранение; действия должны иметь понятный результат и не оставлять UI в ложном состоянии.
- Не подделывай маршрутизацию, статистику популярности, исторические факты или источник данных. Если реального поставщика пешей геометрии или достоверных метрик нет, отдели такие значения как отсутствующие, используй существующий провайдер проекта либо оставь понятное расширяемое поведение без выдуманных чисел.
- Не включай события в MVP.

## Frontend, backend и контракт API

- Сначала перечисли текущие frontend-приложения (включая desktop и Android), backend, хранилище, API-операции и схемы. Не считай, что desktop и Android имеют одинаковую степень готовности.
- Проверь, что каждый пользовательский сценарий использует реально реализованный API, а не только локальные заглушки. Сопоставь ручки OpenAPI, backend роуты/обработчики и frontend-клиент: методы, пути, авторизацию, параметры, nullable поля, пагинацию, ошибки и статусы.
- Добавляй/меняй API только там, где это требуется сценариями. Сохраняй обратную совместимость или явно обновляй всех потребителей и спецификацию в одном изменении.
- Если OpenAPI является источником истины, обнови его и выполни предусмотренную проектом кодогенерацию; не редактируй сгенерированные файлы вручную. Проверь чистый повторный запуск генератора и отсутствие незапланированного diff.
- Соблюдай текущие соглашения проекта, валидацию входных данных, обработку ошибок, транзакции, безопасность и миграционную стратегию. Не помещай секреты/ключи записи в браузерный или Android-клиент.
- Дизайн Figma можно редактировать через MCP только в рамках описанной концепции и найденных расхождений. Перед любыми изменениями существующих Figma фреймов внимательно проверь выбранные страницы/узлы; сохраняй исходные варианты и не удаляй чужую работу. Загрузи обязательную инструкцию `figma-use`, прежде чем вызывать инструмент записи. Если MCP поддерживает запись, внеси согласованные правки в нужные фреймы, сохрани их и проверь результат повторным чтением/скриншотом. Если доступ только на чтение — реализуй UI в коде и сообщи об ограничении.

## Качество и проверка

Добавь или обнови тесты, покрывающие критические сценарии и ошибки:

- backend: валидация, обработчики маршрутов, упорядоченные остановки, сохранение/чтение, авторизация и ошибки хранилища там, где это применимо;
- frontend: состояния загрузки/ошибки/пустых данных, поиск мест, сборка маршрута, порядок остановок и вызовы API;
- контракт: соответствие схемы OpenAPI серверу и сгенерированному клиенту.

Запускай релевантные проектные проверки и тесты, а также сборку затронутых приложений. Если среда не позволяет поднять БД, эмулятор Android, провайдера карт или интеграционный сервис, запусти доступные проверки и перечисли точную непроверенную часть. Не заявляй о тестах, которые не запускал. Не меняй несвязанные файлы ради прохождения проверок.
